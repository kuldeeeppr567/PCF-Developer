# Security Posture

> Local-Only — All AI-Assisted Work Stays on Your Machine

## Overview

The PCF Developer Agent operates within a secure, local-first architecture. All code generation, file editing, and AI interactions happen on the developer's local machine. No customer data, generated code, or prompts are stored externally beyond the standard GitHub Copilot service boundary.

## Key Security Principles

| # | Principle | Description |
|---|-----------|-------------|
| 1 | **All code stays local** | Generated PCF controls, manifests, CSS, and TypeScript remain on your filesystem. Nothing is uploaded unless you explicitly deploy. |
| 2 | **Copilot does not retain context** | GitHub Copilot processes prompts and returns completions — it does not store or learn from your code. |
| 3 | **Authentication is separate** | The agent never handles or stores your Power Platform credentials. `pac auth` manages auth profiles independently via the CLI. |
| 4 | **Deployment requires explicit action** | No control is ever deployed automatically. The agent always confirms the target environment before pushing. |
| 5 | **Generated code follows security best practices** | All PCF controls generated by this agent follow OWASP guidelines — no `innerHTML` with unsanitized content, no eval(), CSP-compatible patterns. |

## What the Agent CAN Access

| Resource | How | Purpose |
|----------|-----|---------|
| Local filesystem | File read/write tools | Create and edit PCF control files |
| Terminal | Execute commands | Run `pac`, `npm`, `dotnet` commands |
| Attached images | Vision analysis | Analyze screenshots for image-to-PCF |
| Web URLs | Fetch tool | Look up documentation references |

## What the Agent CANNOT Access

| Resource | Why |
|----------|-----|
| Your Power Platform credentials | Managed by `pac auth` — agent has no access to tokens/secrets |
| Remote environments directly | Deployment only happens through CLI commands you approve |
| Other repositories or files outside workspace | Sandboxed to the open workspace folder |
| External APIs or databases | No network calls unless you explicitly instruct it |
| Browser cookies/sessions | No browser access beyond URL content fetching |

## Generated Code Security Standards

All PCF controls produced by this agent follow these security practices:

### XSS Prevention
- Never uses `innerHTML` with user-provided data
- Uses `textContent` or DOM APIs for rendering dynamic content
- Sanitizes any values before rendering

### Input Validation
- Validates bound property values before processing
- Handles null/undefined gracefully
- Type-checks all external inputs

### CSP Compatibility
- No inline event handlers (`onclick="..."`)
- No `eval()` or `new Function()`
- No external script loading
- All styles via CSS files or `style` property assignment

### Dependency Security
- Minimal third-party dependencies
- Run `npm audit` after installing packages
- No packages with known vulnerabilities in generated scaffolds

## Credential Management

The agent relies on the Power Platform CLI (`pac`) for authentication:

```bash
# Authentication is managed by pac CLI — NOT by the agent
pac auth create --url https://yourorg.crm.dynamics.com

# Credentials are stored in pac's secure credential store
# The agent only invokes pac commands — it never reads credentials
```

**The agent will never:**
- Ask you to paste credentials into chat
- Store connection strings in code files
- Hardcode environment URLs in generated controls
- Bypass pac auth for deployment

## Risk Boundaries

| Risk | Mitigation |
|------|-----------|
| Agent generates insecure code | Skills enforce XSS prevention, input validation patterns |
| Accidental deployment to production | Agent always asks to confirm environment before `pac pcf push` |
| Sensitive data in prompts | Copilot does not retain prompts; use generic descriptions |
| Malicious npm packages | Only well-known packages are suggested; `npm audit` recommended |
| Unauthorized file access | Agent is sandboxed to the open VS Code workspace |
